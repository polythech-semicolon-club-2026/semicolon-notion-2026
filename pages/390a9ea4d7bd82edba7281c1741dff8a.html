깃 & 깃허브 협업 마스터

이 자료 하나로 Git 협업이 가능한 개발자 수준에 오르는 것이 목표입니다.
코드만 잘 짜는 게 아니라, 팀과 함께 일할 수 있는 개발자가 되어봅시다.

📋 전체 목차

1부. Git & GitHub 핵심 개념

  1. 버전 관리 시스템이란
  1. Git vs GitHub — 무엇이 다른가
  1. 핵심 용어 완전 정복 — Repository / Commit / Push / Pull / Clone / Fork
  1. 브랜치(Branch) — 평행 우주 작업 공간
  1. Merge & Conflict — 합치는 원리와 충돌 해결
  1. Pull Request(PR) — 코드 리뷰 문화의 시작
  1. Issue — 할 일을 코드와 함께 추적하는 방법

2부. 협업 전략과 문화

  1. 왜 협업 전략이 필요한가
  1. Git Flow vs GitHub Flow
  1. 팀장 vs 팀원의 역할 분담
  1. 커밋 메시지 컨벤션
  1. 브랜치 네이밍 컨벤션
  1. Issue 컨벤션 & 라벨
  1. README.md & .gitignore

3부. 실습 — 팀 자기소개 페이지 만들기

  1. [팀장] 레포 생성, 뼈대 코드 Push & GitHub Pages 배포
  1. PR 컨벤션 & 템플릿
  1. [팀원] Clone → 브랜치 생성 → 자기소개 섹션 작성 → Commit & Push
  1. [팀장] PR 확인 → 코드 리뷰 → Approve → Main Merge
  1. [전원] Main Pull → footer 동시 수정 → Commit & PR 요청
  1. [팀장] 충돌 발생 화면 시연 → VS Code GUI로 해결 과정 설명
  1. [전원] 직접 충돌 해결 → add → commit → push → PR → Main Merge → Pages 확인
