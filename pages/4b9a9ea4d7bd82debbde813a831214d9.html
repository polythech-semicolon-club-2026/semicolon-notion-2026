개발 추천 제안

1. Git

main : 최종 안정 코드
dev : 개발 통합 브랜치
feature : 기능별 작업 브랜치

docs는 dev와 그 하위에서만 관리하고 main에 푸시되지 않도록 해야함main에는 일단 readme만 올려놓고, 바로 dev 브렌치 파서 docs 만들면 됨. readme는 pdf 때리고 만들어달라고 하셈.

main readmed에는 프로젝트 제목이랑 이런 프로그램이다만 일단 간략하게 넣어 두고, dev에서 수정해서 어떤식으로 개발할건지 git 관리 전략이나 커밋 규칙, 개발 규칙, 개발 흐름, 최종으로 어떤 프로그램 개발할건지 같은거 싹 정리해서 미리 만들어두면 AI 때릴때 다 같이 그거 넣고 그거 기준으로 때리면 되서 작업 통일성이 생기니까 꼭 만들어두시길

.env 나 config 는 탬플릿 만들어서 복제 가능하게 쓰고 ignore 반드시 추가할것. (뭔소린지 모르겟으면 AI ㄱㄱ)

2. 문서 관리 추천?

docs/
├─ 주차별 보고서/ *docx 등 완성된거 여기 보관하시고
├─ 개발문서/ *md 매번 업데이트 되는거고
├─ 참고자료/ * 링크나 pdf 등 공유할수 있게 하면 편하고
└─ 회의록/ *md 회의할때마다 업데이트

개발 문서 같은 경우 소통용과 전체 프로세스용으로 나누면 편함. 소통용에는 “최종 수정일, 수정인, 개발 내용, 수정 및 추가 파일, 발생 문제, 해결 방법, 해결 여부, 다음 예정 작업”
이런거 넣고, 개발 프로세스 문서에는 “Phase 별 MVP 범위, 기능명세, 비기능명세, 담당자, 완료일, 진행상황, MVP 개발 완료시 추후 추가하면 좋을 것 같은 기능 등” 넣어두면 관리하기 용이함
